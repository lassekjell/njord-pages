02

Project directory

Separata kataloger under Njord: branding (typsnitt, färger, templates), en per fartyg med teknisk detalj, en per projekt. Varje katalog har sin egen CLAUDE.md som pekar till rätt Markdown-filer: "för propelleranalys, läs denna fil", "motordata och sjöprov ligger här".

Separate directories under Njord: branding (fonts, colors, templates), one per vessel with technical detail, one per project. Each directory has its own CLAUDE.md pointing to the right Markdown files: "for propeller analysis, read this file", "engine data and sea trials are here".

03
Sessionsdisciplin
Session discipline

Jag ber aldrig Claude att söka information själv — det är tidsödande och blir lätt fel. Istället matar jag in verifierad dokumentation. Vi börjar alltid i planeringsfas: förstå problemet, kartlägg behoven, bygg strukturen. Först därefter producerar vi.

I never ask Claude to search for information itself — it's time-consuming and error-prone. Instead I feed verified documentation. We always start in planning phase: understand the problem, map the needs, build the structure. Only then do we produce.

Viktigaste principen
The key principle

Filer är output — Markdown är sanningen

Alla AI-verktyg kan producera en Excel-fil med mängder av data ur sitt minne efter en enda prompt. Men när du vill ändra en cell, en kolumn, en formel — då går det ofta helt fel. Du får börja om.

Min lösning: Excel-filen är bara en output. All data, alla antaganden, alla beräkningsgrunder ligger i Markdown-filer som Claude läser som källdata. Filen är ett resultat — inte källan.

Files are output — Markdown is the truth

Any AI tool can produce an Excel file with tons of data from memory after a single prompt. But when you want to change a cell, a column, a formula — it often goes completely wrong. You have to start over.

My solution: The Excel file is just an output. All data, all assumptions, all calculation bases live in Markdown files that Claude reads as source data. The file is a result — not the source.

6 The Language

Markdown — simple & powerful

Markdown is a simple text syntax that lets you focus on content instead of formatting. It's Claude's native language — and it should be yours too.

# Heading 1 ## Heading 2 Regular text with **bold** and *italic*. - Bullet list - With sub-items - Like this | Column A | Column B | |----------|----------| | Data 1 | Data 2 | Status: ✅ Done 🔴 Critical ⏳ In progress

Varför Markdown?

Versionshanterat

Textfiler kan enkelt spåras, jämföras och säkerhetskopieras. Du ser alltid vad som ändrats.

Konverterbart

Från .md till Word, PDF, HTML, PowerPoint. Ett format — många outputs.

AI-optimerat

Claude läser och skriver Markdown nativt. Det ger bäst resultat och snabbast arbetsflöde.

Why Markdown?

Version controlled

Text files can be easily tracked, compared and backed up. You always see what changed.

Convertible

From .md to Word, PDF, HTML, PowerPoint. One format — many outputs.

AI-optimized

Claude reads and writes Markdown natively. It gives the best results and fastest workflow.

8 Workflow

What does a session look like?

From idea to delivery — typical workflow when I work with Claude.

1. Öppna projektet

Peka Claude på rätt mapp. CLAUDE.md laddar automatiskt — kontexten är satt.

2. Beskriv uppgiften

Kort och konkret: "Skapa en riskmatris för hybridinstallationen" eller "Skriv mail till Scania om DW6-leverans".

3. Claude arbetar

Läser relevanta filer, ställer klargörande frågor, producerar materialet med rätt formatering.

4. Iterera & förfina

"Lägg till en kolumn för kostnad" eller "Gör tonen mer formell". Snabba justeringar.

5. Leverera

Färdigt dokument sparas direkt i projektet. Klart att använda, skicka eller dela.

1. Open the project

Point Claude to the right folder. CLAUDE.md loads automatically — context is set.

2. Describe the task

Short and concrete: "Create a risk matrix for the hybrid installation" or "Write an email to Scania about DW6 delivery".

3. Claude works

Reads relevant files, asks clarifying questions, produces the material with correct formatting.

4. Iterate & refine

"Add a column for cost" or "Make the tone more formal". Quick adjustments.

5. Deliver

Finished document saved directly in the project. Ready to use, send or share.

Evaluation Template Pack

A structured template for evaluating technical products (propeller, engine, battery, DP). Data lives in YAML, one build script produces four formats from the exact same numbers. Every value must have a source or the build fails. Weights sum to 100. Sensitivity analysis is default.

17 The honesty

Where AI falls short

Trust is built on honesty. Here is what Claude is bad at, and the guard we put against each one.

⚠️

Hittar på

Makes things up

En modell kan ange en siffra eller en paragraf med full säkerhet och ändå ha fel. Spärr: vi matar in verifierad dokumentation och varje värde ska ha en källa.

A model can state a number or a clause with full confidence and still be wrong. Guard: we feed verified documentation and every value must cite a source.

📅

Saknar färsk verklighet

No fresh reality

Claude vet inte vad som hände i morse, vilken offert som kom in sist eller vad som står i ett system den inte fått se. Spärr: vi ger den färska filer och ber den aldrig gissa.

Claude does not know what happened this morning, which quote arrived last or what sits in a system it has not seen. Guard: we give it fresh files and never ask it to guess.

🧮

Snubblar på tung matematik

Stumbles on heavy math

Långa beräkningskedjor kan bli fel om de görs i huvudet. Spärr: beräkningar läggs i kod eller kalkylark som går att granska, inte i löpande text.

Long calculation chains can go wrong when done in the head. Guard: calculations live in code or spreadsheets that can be reviewed, not in running text.

⚖️

Bär inget ansvar

Carries no responsibility

En modell kan inte hållas ansvarig för ett klassningsbeslut eller en säkerhetsbedömning. Spärr: människan signerar, alltid.

A model cannot be held accountable for a classification decision or a safety assessment. Guard: the human signs, always.

Frequently asked

The objections that actually come up, with straight answers.

Tar AI mitt jobb?

Will AI take my job?

Nej. Den tar bort skrivandet, formaterandet och letandet, inte omdömet. Du fattar fler beslut på samma tid, med bättre underlag.

No. It removes the writing, formatting and searching, not the judgment. You make more decisions in the same time, with better support.

Är det tillåtet att använda?

Are we allowed to use it?

Ja, inom våra ramar. Publika och egna data: ja. Persondata och sekretessbelagt: nej. Vid tveksamhet, fråga först.

Yes, within our boundaries. Public and own data: yes. Personal data and confidential material: no. When in doubt, ask first.

Vad händer om den har fel?

What if it gets something wrong?

Därför signerar en människa. Vi matar in verifierad data, vi ber aldrig modellen gissa, och vi granskar allt som går vidare.

That is why a human signs. We feed verified data, we never ask the model to guess, and we review everything that goes out.

Måste jag kunna koda?

Do I need to know how to code?

Nej. Allt börjar i vanlig text. Att skriva ett tydligt mail räcker för att komma igång.

No. It all starts in plain text. Writing a clear email is enough to get going.

Var sparas det jag matar in?

Where is what I enter stored?

I avgränsade projektmappar. Källdata stannar lokalt, och det som publiceras ligger bakom lösenord.

In scoped project folders. Source data stays local, and what gets published sits behind a password.

Lär den sig av våra hemligheter?

Does it learn from our secrets?

Vi behandlar allt som matas in som halvpublikt och håller känsligt material utanför. Bygger vi något känsligt gör vi det i en granskad lösning först.

We treat everything entered as semi-public and keep sensitive material out. If we build something sensitive, we do it in a reviewed solution first.
